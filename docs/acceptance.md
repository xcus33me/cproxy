# Приёмка на вашей машине и VPS

Эти проверки не заменяются offline fixture-тестами. Перед изменениями SSH сохраняйте запасной административный сеанс/консоль. cproxy не управляет VPS автоматически.

1. Установите unattended с отдельным ограниченным ключом; выйдите из сеанса и войдите снова (или перезагрузитесь). Без ручного терминала `status` должен показать сервис/задачу и порт, `test` — проверенный egress VPS.
2. Откройте обычный Firefox и `proxyctl browser`. Сравните IPv4/доступный IPv6, путь профиля, DNS и WebRTC по `docs/firefox.md`. Сначала проверьте сеть, затем входите в Claude.
3. Запустите `claude-vpn --help`, затем интерактивный Claude и `/status`; проверьте proxy. OAuth открывайте в выделенном Firefox. Убедитесь, что аргументы, exit code и поведение Ctrl+C подходят вашей версии CLI.
4. Остановите sing-box. Новая некэшированная страница в уже открытом Claude Firefox должна показать ошибку. Wrapper должен отказать запускать Claude. Обычный Firefox и рабочие SSH/GitLab/PostgreSQL/Portainer должны продолжать работать.
5. Отдельно воспроизведите недоступный VPS/неверный SSH user через reconfigure (старый конфиг должен восстановиться) или контролируемый SSH-разрыв при сохранённом аварийном доступе. При живом локальном порте `test` должен ошибаться, не показывать direct IP как proxy. После восстановления SSH новый запрос должен работать; при необходимости restart. Не блокируйте единственный административный SSH-путь.
6. Сравните рабочие инструменты в обычном терминале до/после. Для дочерних команд Claude оцените влияние proxy env, добавьте явные внутренние suffix и `local_tests`, проверьте их напрямую и через proxy.
7. Повторите status/test при Amnezia off/on, проверьте маршрут до VPS. Не предполагается, что два маршрута независимы.
8. Повторите установку, проверьте сохранение настроек/профиля и отсутствие второго процесса/задачи. Внесите неверный кандидат через params и убедитесь, что рабочая версия сохранена. Удалите, проверьте сохранение оригинального ключа/Firefox-профиля и повторную установку.
9. Для session проверьте unlock/lock, неверную passphrase, новый вход и удаление runtime copy. Windows: после аварии проверьте остаточный файл и выполните lock; он не гарантированно исчезает автоматически.

Системный proxy, DNS, routes и Amnezia-конфигурация должны оставаться прежними. Приёмка фоновых агентов/IDE требует отдельной пользовательской настройки и проверки; CLI-wrapper сам по себе их не покрывает.
