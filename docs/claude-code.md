# Claude Code

Официальная документация подтверждает `HTTP_PROXY`, `HTTPS_PROXY`, lowercase варианты и `NO_PROXY`. SOCKS непосредственно Claude Code не поддерживает, поэтому wrapper использует mixed HTTP CONNECT. Более приоритетная lowercase переменная переопределяется одновременно с uppercase. Унаследованное `NO_PROXY=*` не сохраняется.

Перед каждым запуском — HTTPS запрос через proxy, правильный IPv4 и pin либо сравнение с direct. Если direct недоступен и pin не задан, wrapper отказывается стартовать: невозможно сравнить выходы. Получите egress IPv4 через доверенную консоль VPS и заполните `settings.json.expected_ips`. Совпадение выходов при Amnezia бывает законным; проверенный pin разрешает его. Недоступный IPify тоже блокирует новый запуск. Это сознательная проверка готовности, не автоматический переход на другое подключение.

Wrapper запускает оригинальную команду `claude`, передавая аргументы без eval и сохраняя код завершения. `--help` также проходит сетевую проверку. На Windows поддерживаются native `claude.exe` и стандартная npm-установка через соседний `node_modules/@anthropic-ai/claude-code/cli.js` и `node.exe`; произвольные .cmd launchers не исполняются через `cmd /c`, чтобы не терять специальные символы аргументов.

Proxy env задаются только дочернему процессу. В Bash `exec env ...`; PowerShell использует ProcessStartInfo без временной правки `$env:` родителя. Fish вызывает тот же Bash-wrapper. Файлы Claude settings не меняются.

## Дочерние команды и рабочая сеть

Дети Claude наследуют proxy env. HTTP GitLab, npm, curl и другие инструменты, которые их понимают, могут пойти через cproxy. SSH и PostgreSQL обычно не используют HTTP proxy env, но обещать это для всех клиентов нельзя. cproxy сам не меняет их маршруты.

Loopback внесён точными адресами в `NO_PROXY`. Частные IP и `.local` маршрутизируются direct самим sing-box, даже если версия инструмента игнорирует `NO_PROXY`. Для корпоративных доменных имён задайте точный внутренний suffix через параметры установщика. Не добавляйте Anthropic или широкие публичные suffix в bypass; это отвергается генератором.

Рабочие команды проще выполнять в обычном терминале. Для явно direct дочерней команды в Bash можно запустить `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy -u NO_PROXY -u no_proxy git status`; это пример снятия proxy только у конкретного процесса. Не используйте такой способ для запросов Claude.

Приложение может игнорировать env, а пользовательские Claude settings могут переопределить сетевые настройки. Wrapper не является firewall и не обещает контролировать любой код, выполняемый агентом. Проверьте `/status` в Claude и конфигурацию ваших managed/user/project settings; cproxy автоматически их не переписывает.

## Фоновые агенты и IDE — отдельная опция

Официально фоновый supervisor живёт отдельно от запускающего терминала и наследует env первого запуска. Уже работающий supervisor может не получить wrapper env. Поэтому `claude-vpn --bg` и запуск `agents` блокируются. `/background`, команды агентов из уже работающего процесса и будущие способы запуска требуют внимания пользователя: shell wrapper не способен надёжно блокировать их все.

Если фоновые агенты нужны, **вручную и после осознанного согласия** добавьте HTTP/HTTPS proxy env в user/managed Claude settings, удалите конфликтующие lowercase env/broad NO_PROXY и остановите существующий supervisor командой `claude daemon stop --any`. Проверьте настройки и отказ при остановке proxy до запуска фоновой сессии. Это меняет область действия: proxy получат все соответствующие Claude-сеансы пользователя, а не только wrapper. Для launcher используется документированный `processWrapper`; cproxy не внедряет его автоматически.

IDE/Claude Desktop могут управлять provider connection сами и читать proxy только из определённых settings scopes. Не считайте запуск IDE из wrapper доказательством проксирования. Используйте CLI в терминале IDE через `claude-vpn` для поддержанного сценария. OAuth URL открывайте в выделенном Firefox, не случайном основном браузере.

Источник: [официальная network-config документация Claude Code](https://code.claude.com/docs/en/network-config), включая отдельные разделы background agents и Desktop settings scopes.
