# cproxy: проект переписывания на Go

Статус: согласовано пользователем («Добро»), реализовано 2026-10-11.

## Задача пользователя

Простой поддерживаемый клиент для Windows и Linux: запустить приложение,
указать свой VPS и пользоваться Claude в браузере и Claude Code. Доступ к
рабочим сайтам и локальной сети должен сохраняться. Основная логика — Go;
интерфейс huh сохраняется. Старую структуру и команды сохранять необязательно.

Предположения: VPS уже существует, доступен по SSH и разрешает TCP forwarding;
есть файловый SSH-ключ. По умолчанию предлагается отдельный Firefox для Claude.
Этот браузерный сценарий принят в согласованном проекте.

Программа может обеспечить выбранный маршрут и отказ при потере прокси.
Она не может гарантировать доступность Claude или отсутствие блокировки аккаунта.
РФ отсутствует в опубликованном списке поддерживаемых Anthropic стран; смена
исходящего IP не меняет правил сервиса.

## Что подтверждено в исходном коде до переписывания

- Go-код в `internal/app/runtime.go` ищет скрипты и передаёт им команды через
  Bash/PowerShell. Самостоятельного клиента сейчас нет.
- Две реализации повторяют валидацию, генерацию конфигурации, установку,
  проверку SSH, управление процессами и запуск приложений.
- Linux требует systemd user session и несколько внешних утилит; автоматическая
  установка зависимостей ориентирована на Arch. Windows использует Task Scheduler,
  PowerShell, OpenSSH и winget.
- Существующая сетевая схема уже обходится без TUN: loopback mixed proxy,
  SSH outbound и отдельный Firefox. Этот принцип подходит задаче.
- Внутренний hostname без настроенного suffix уходит через SSH даже тогда,
  когда локальный DNS разрешает его в частный IP. Это описано и в старой документации.
- Режим session создаёт расшифрованную копию SSH-ключа на диске.
- Большинство проверок установщика подменяют systemctl, sing-box и сеть.
  Прохождение этих тестов не подтверждает работу реального VPS и браузера.

Без сведений об ошибке реального подключения нельзя назвать единственную
причину пользовательского «почти не работает». Перечисленное — подтверждённые
свойства архитектуры, а не воспроизведённый сбой на пользовательском компьютере.

Проверки исходного состояния 2026-10-11: `go test ./...` и `go vet ./...`
прошли с отдельными GOCACHE/GOMODCACHE в `/tmp`. Системный кеш зависимостей
содержит пустые Go-файлы, поэтому для проверки зависимости скачаны заново;
это свойство текущего окружения, не ошибка репозитория. Python suite:
33 теста, 30 успешных, 2 ошибки ожидания экранов мастера, 1 пропуск настоящего
sing-box check из-за отсутствующего binary. Оба падающих UI-теста повторно
упали при отдельном запуске. Вывод показывает попадание первых символов
следующего поля в предыдущее; причина в UI или синхронизации PTY-теста пока
не установлена. VPS и реальная Windows в этом аудите не проверялись.

## Рассмотренные варианты

1. **Go управляет отдельным sing-box — рекомендуется.** Сохраняем готовый
   сетевой движок, переносим всю прикладную логику в Go. Архив содержит два
   исполняемых файла; пользователь запускает только cproxy.
2. **Полностью свой SSH/HTTP-прокси на Go.** Один исполняемый файл, но придётся
   поддерживать CONNECT, SOCKS, таймауты, маршрутизацию и восстановление соединений.
   Для цели «минимум проблем и обслуживания» это лишняя сетевая реализация.
3. **Системный TUN со split routing.** Подключает обычные приложения прозрачно,
   но требует прав администратора и аккуратной работы с DNS, корпоративными
   маршрутами и сторонними VPN. Для текущего сценария сложнее первого варианта.

## Поведение новой версии

Готовые архивы Windows/Linux amd64/arm64 содержат `cproxy`, совместимый
`sing-box` и необходимые лицензии. На пользовательском компьютере сборка,
Go, Bash, PowerShell, jq, curl, systemd и установка пакетов не нужны.
Firefox и Claude Code должны быть установлены отдельно; приложение объясняет,
что отсутствует. Для разработки достаточно стандартных Go-команд.

Первый запуск показывает три поля: сервер, пользователь и SSH-ключ.
Порты, путь к sing-box и исключения локальной сети доступны в дополнительных
настройках. Указание `user@host` допустимо как удобный способ заполнить поля;
IPv6 и нестандартные порты разбираются без shell-интерполяции.

После успешной проверки появляются действия: открыть Claude, запустить Claude
Code, проверить подключение, настройки, остановить прокси и выйти.
Выход из меню оставляет уже запущенный фоновый процесс; остановка — отдельное
действие. После перезагрузки достаточно снова открыть cproxy. Автозапуск при
входе в ОС не входит в первую версию: он не требуется исходной задаче.

CLI: `setup`, `start`, `stop`, `status`, `doctor`, `browser`, `claude [args]`,
`logs`, `run` для диагностики в переднем плане. Аргументы, текущий каталог,
терминальный ввод/вывод и код завершения Claude Code сохраняются.

## Сеть и локальные сайты

Обычные приложения продолжают пользоваться существующими маршрутами и DNS.
cproxy не меняет системный прокси, сетевые интерфейсы или firewall.

Отдельный Firefox получает SOCKS5 с разрешением внешних имён на VPS;
Claude Code получает HTTP-прокси через environment только своего процесса.
Все внешние назначения этих приложений по умолчанию идут через VPS. Это
покрывает новые домены авторизации/CDN без постоянного обновления allowlist.
TLS остаётся между приложением и целевым сайтом.

Частные IP, loopback, `.local` и явно введённые корпоративные suffix идут
напрямую. Исключения применяются внутри sing-box. Домены Claude имеют
приоритет над исключениями; слишком широкие и пересекающиеся исключения
отвергаются. Унаследованные proxy/NO_PROXY переменные не могут отключить
этот маршрут в запущенном через cproxy Claude Code.

Для неизвестного корпоративного имени нельзя одновременно гарантировать
локальное обнаружение и отсутствие локальных DNS-запросов внешних доменов.
Поэтому автоматическое разрешение всех внешних имён локальным DNS не добавляем:
в обычном браузере рабочие имена работают как раньше, а для проксируемых
приложений пользователь задаёт корпоративный suffix в понятном поле.

Firefox использует постоянный выделенный профиль. Отключены прямой fallback,
DoH, WebRTC и HTTP/3. Это ограничивает звонки и другие функции с UDP;
ограничение явно описывается. Внешняя OAuth-ссылка должна открываться в этом
профиле. Приложение не обещает контролировать браузер, открытый самой ОС,
или инструменты Claude Code, которые игнорируют proxy environment.

При недоступном VPS запросы через прокси завершаются ошибкой. Переход на
прямое соединение для внешних сайтов не предусмотрен.

## Ответственности Go-кода

- `config`: небольшая версионированная модель пользовательских настроек,
  проверка значений и безопасная запись. Конфигурация sing-box генерируется
  типизированным Go-кодом, без редактируемого JSON-шаблона и jq.
- `ssh`: чтение и проверка ключа через `golang.org/x/crypto/ssh`, подключение,
  проверка закреплённого host key и импорт стандартного known_hosts.
- `engine`: генерация конфигурации, проверка совместимости sing-box,
  запуск, ограниченный журнал и восстановление после завершения ребёнка.
- `session`: один фоновый процесс того же Go-бинарника, проверка готовности,
  управление и остановка. Небольшие файлы с build tags содержат только
  платформенные детали процессов, блокировки и файловых прав.
- `launch`: обнаружение Firefox/Claude Code, профиль браузера и environment
  дочерних процессов; Windows wrapper `.cmd` поддерживается только там,
  где этого требует способ установки Claude Code.
- `app`: формы huh и разбор команд. UI не содержит сетевую логику.

Не создаём универсальный service framework, систему плагинов или абстракции
для нескольких сетевых движков. Пакеты разделяются по ответственности;
конкретные границы уточняются в плане реализации.

## SSH, пароли и управление процессом

Сохранённый host key обязателен. При первом неизвестном подключении показываем
fingerprint и предлагаем подтвердить его; для известного сервера используем
существующий pin/known_hosts. Изменение ключа блокирует подключение и требует
отдельного осознанного сброса. Это не заменяет независимую проверку первого ключа.

Пароль зашифрованного SSH-ключа запрашивается скрытым полем и не сохраняется.
Он передаётся фоновому процессу и sing-box по stdin, не в argv, environment,
журнале или конфигурационном файле. Исходный ключ не меняется, расшифрованная
копия не создаётся. После завершения сессии пароль нужен снова.
Отдельный процесс sing-box поддерживает `-c stdin` в проверенном исходном коде
версии 1.14.3; при перезапуске supervisor повторно передаёт конфигурацию.

Управление фоновым процессом — небольшой HTTP endpoint на случайном loopback
порту с секретным случайным токеном, сохранённым в приватном runtime-файле.
Только status/stop; проверяем метод, авторизацию, Origin и ограничиваем запросы.
Блокировка на уровне ОС предотвращает две сессии. PID сам по себе не является
основанием для завершения процесса; чужой процесс на proxy-порту — ошибка.
На Windows применяются native ACL и Job Object для ребёнка; на Linux —
приватные права и завершение ребёнка при смерти supervisor.

Готовность означает ответ собственного supervisor и успешный HTTPS-запрос
через явно указанный прокси. Открытого TCP-порта недостаточно. Исходящий IP
показывается как диагностика; равенство обычного и проксируемого IP само по
себе не ошибка и не доказательство обхода прокси. Явный pin IP необязателен.

## Замена старой версии

Из исходников удаляются старые Linux/Windows установщики, wrapper-скрипты,
JSON-шаблон, jq-валидатор и тесты удалённых компонентов. Документация и CI
переписываются вокруг нового запуска и проверок Go.

Существующую установленную версию не удаляем молча. Новый клиент распознаёт
старые настройки, предлагает импорт соединения, suffix и host pin; проверяет
маркер принадлежности старого сервиса/задачи перед его отключением.
Профиль Firefox и исходные ключи сохраняются. Новая сессия запускается после
освобождения старого proxy-порта; при ошибке перехода восстанавливается
предыдущая конфигурация и состояние. Старые каталоги не удаляются рекурсивно.

## Проверка реализации

Go-тесты проверяют ошибки конфигурации, приоритет исключений, сохранение
аргументов/environment, encrypted key без записи секрета и изменение host key.
Локальный тест с временным SSH-сервером и настоящим sing-box проверяет HTTP,
SOCKS с серверным DNS, недоступность VPS, несовпадение ключа и восстановление.
Проверяются одновременный start, чужой занятый порт, stop, завершение supervisor
и отсутствие оставшегося дочернего sing-box.

CI выполняет тесты на настоящих Linux и Windows runner; четыре цели сборки
проверяются отдельно. Smoke-проверка huh подтверждает настройку и отмену.
Реальные Firefox, OAuth, рабочая сеть и пользовательский VPS требуют отдельной
проверки в соответствующем окружении; кросс-компиляция её не заменяет.
