# Архитектура и параметры

Единственный сетевой клиент — sing-box. Linux/Bash+jq и Windows/PowerShell читают общий `config/sing-box.json.tpl` как JSON и меняют поля сериализаторами. Строковые подстановки через sed не используются; Windows backslash и пробелы в путях сохраняются. Минимальная версия 1.12 нужна для нового формата local DNS server и `domain_resolver`.

Вход: mixed, loopback IPv4, системный proxy отключён. HTTP CONNECT сохраняет TLS от приложения до сайта; TLS не перехватывается. SSH outbound открывает TCP forwarding каналы на существующем SSHD. UDP явно отвергается. Никаких интерфейсов, сетевых firewall-правил и системных DNS-изменений.

Порядок правил: reject UDP → suffix Anthropic/Claude в SSH → явные частные CIDR в direct → явные внутренние suffix в direct → final SSH. Список защищённых suffix включает `anthropic.com`, `claude.ai`, `claude.com`, `claudeusercontent.com`, `claudemcpcontent.com`. Остальные публичные сайты также идут по final SSH; отдельный allowlist внешних сайтов не нужен.

Исключения работают только для соединений, уже переданных локальному proxy. Domain suffix сравниваются без локального DNS-resolution внешних сайтов. Поэтому неизвестный внутренний hostname, даже разрешающийся в `10.x`, остаётся SSH, пока вы явно не добавите его внутренний suffix. В direct DNS используется штатный системный resolver; внешние имена SSH forwarding разрешаются сервером. Системный resolver также нужен для имени самого VPS. Можно указать IP VPS, чтобы не требовать bootstrap DNS.

CIDR разрешены только внутри loopback/RFC1918 и перечисленные локальные IPv6 диапазоны. Произвольные публичные CIDR, `0.0.0.0/0`, `::/0`, предки защищённых доменов (`com`, `ai`, `org`) и их поддомены отвергаются. Для IP-literal частной сети нельзя определить «принадлежит ли он Anthropic»; поэтому исключения должны соответствовать реально внутренней сети. Глобальный `NO_PROXY` здесь не механизм безопасности.

Host key обязательно непустой. Интерактивный установщик выбирает его автоматически: сначала существующая конфигурация cproxy, затем стандартные OpenSSH known_hosts, затем доверие первому подключению (TOFU). Ручного ввода fingerprint нет; неизвестный ранее сервер при первой настройке не проходит независимую проверку подлинности. Изменённый сохранённый ключ не принимается автоматически. Его алгоритм фиксируется вместе с ключом, чтобы сервер с несколькими host keys не согласовал другой ключ. Для RSA разрешаются `rsa-sha2-512`/`rsa-sha2-256`; SSH RSA/SHA1 не включается. Сертификаты SSH CA/FIDO/hardware keys в MVP не реализованы; используйте обычный файловый Ed25519/RSA/ECDSA ключ.

CLI проверяет сетевую часть конфига на соответствие шаблону: добавление outbound, direct final, TUN, расширенные rules или небезопасные SSH параметры запрещены. Настройки `log` разрешены, но по умолчанию только warn; debug может содержать адреса назначения. Конфиг содержит публичные connection details и путь к ключу, сам ключ и пароли в JSON не помещаются.

## Явные параметры

Проще использовать интерактивный мастер. Для внутренних suffix/нестандартных private CIDR:

```bash
cp config/params.example.json params.local.json
chmod 600 params.local.json
```

Заполните пустые `server`, `user`, абсолютный `key` и `host_key` в локальном редакторе. `host_key` — строго строка `algorithm BASE64`, без hostname/comment. Получите её через доверенную консоль, например `sudo cat /etc/ssh/ssh_host_ed25519_key.pub`; перенесите первые два поля. `expected_ips` — исходящий IPv4, независимо проверенный на VPS. Это не обязательно SSH IP.

На Windows:

```powershell
Copy-Item .\config\params.example.json .\params.local.json
notepad .\params.local.json
```

Windows пути в JSON записывайте с удвоенным `\\`, например `C:\\Users\\User Name\\.ssh\\proxy`, или используйте `/`. В интерактивном мастере backslash удваивать не нужно.

`domains`: suffix без ведущей точки, в нижнем регистре, например `local` или ваш конкретный внутренний suffix. Не добавляйте публичный domain только для ускорения. `cidrs`: частные сети или более узкие подсети. Пустые массивы отключают исключения. `local_tests`: ваши внутренние HTTP/HTTPS URL без userinfo/токенов. Наличие тела/HTTP 2xx проверяется curl, это не проверка PostgreSQL протокола.

```bash
./linux/install.sh --params params.local.json
```

```powershell
.\windows\install.ps1 -ParamsFile .\params.local.json
```

При `--params`/`-ParamsFile` оператор подтверждает, что `host_key` уже получен доверенно. Установщик дополнительно сравнивает его с предлагаемыми ключами VPS. При обычной настройке через терминальный мастер допускается TOFU для ранее неизвестного сервера; подробности в ssh-setup.md.

`settings.json` хранит диагностические IP/URL, режим ключа и путь к зашифрованному оригиналу; на Windows также абсолютный путь к binary. Повторная установка сохраняет настройки; явные параметры заменяют только указанные диагностические значения. `--reconfigure` обновляет соединение, сохраняя внутренние исключения. После ручной правки `settings.json` запустите `proxyctl test`.

## Транзакции и процессы

Установщик берёт lock, проверяет кандидата и host key, сохраняет прежнюю установку, публикует новую, обновляет native service/task и проверяет выход в интернет. При ошибке восстанавливаются прежние файлы и активное/включённое состояние. Полное отключение питания во время записи не является атомарной файловой транзакцией: при необходимости используйте сохранённый `.selective-proxy-backup.*` / `.SelectiveProxy.backup.*` в родительском каталоге. Не удаляйте резервный каталог до восстановления.

Linux использует один user unit с `Restart=on-failure`. Windows использует одну задачу на SID и скрытый supervisor, который перезапускает единственного ребёнка через 5 секунд при завершении. PID, время запуска и binary записываются для безопасного stop; совпадение только PID недостаточно. SSH-разрыв обычно обрабатывается самим sing-box на следующих запросах; уже открытая stream-сессия может прерваться. После смены маршрута Amnezia выполните `test`, при необходимости `restart`.

## Терминальное приложение

Интерфейс написан на Go с Huh 2 / Bubble Tea 2 / Lip Gloss 2 из Charm. Сеть по-прежнему обслуживает sing-box; Go не реализует VPN или прокси. `./cproxy` / `.\cproxy.ps1` открывает мастер при первой установке, затем меню. `./linux/install.sh` / `.\windows\install.ps1` без параметров также открывает мастер. Автоматизация через `--params FILE` / `-ParamsFile FILE` сохраняется. Внутренний `--wizard-file` / `-WizardFile` используется интерфейсом: файл создаётся с приватными правами, содержит только параметры подключения и удаляется после применения или ошибки.

Обычная форма содержит адрес, пользователя и ключ. Порты 22 / 2080 и определение режима ключа используются по умолчанию. Shift+Tab возвращает к предыдущему полю; отдельный экран позволяет исправить данные, перейти к дополнительным настройкам или отменить установку. Изменения применяются только после выбора сохранения. Ошибка установки возвращает к редактированию без повторного набора всех полей. Пароль ключа запрашивает OpenSSH, не форма.

Проверка готовности требует запущенного управляемого сервиса/задачи и делает HTTPS-запрос именно через локальный HTTP-прокси; маршрут и закреплённый ключ проверяются конфигурацией sing-box. Различие direct/proxy IP не является условием запуска: VPN может уже использовать тот же выход. `expected_ips` остаётся дополнительной явной проверкой в JSON для тех, кто хочет закрепить независимо проверенный выход. При изменении сервера или SSH-порта через мастер старый IP-pin очищается; при настройке того же подключения сохраняется. `test` по-прежнему сравнивает HTTP/SOCKS5 и показывает direct, IPv4 и доступный IPv6.

После установки бинарник меню и необходимые скрипты находятся в каталоге cproxy, исходники больше не нужны. Windows launcher выполняет временную защищённую копию бинарника, чтобы обновление могло заменить установленный exe. Go 1.25.8+ нужен только для сборки из исходников. Сборка: `go build -o .build/cproxy ./cmd/cproxy` (Windows: `go build -o .build/cproxy.exe ./cmd/cproxy`). CI создаёт архивы Linux/Windows x64/ARM64 с готовым UI и скриптами; публикация архивов сама по себе установку не выполняет.

Команды меню также доступны напрямую: `cproxy setup`, `cproxy browser`, `cproxy claude --help`, `cproxy status`, `cproxy start`, `cproxy stop`, `cproxy restart`, `cproxy test`, `cproxy logs`, `cproxy unlock`, `cproxy lock`. Старые `proxyctl` и `claude-vpn` продолжают работать. Для чтения экрана без интерактивной перерисовки можно задать `CPROXY_ACCESSIBLE=1`.
