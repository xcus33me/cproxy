# Устройство

Один Go-клиент управляет отдельным sing-box. Runtime-скриптов нет.

```text
отдельный Firefox ── SOCKS5 ──┐
                             ├── sing-box (127.0.0.1) ── SSH ── VPS ── внешние сайты
Claude Code ─────── HTTP ─────┘          │
                                      └── direct: явно заданные частные IP и рабочие домены
обычные приложения ─────────────────────── существующая сеть компьютера
```

`config` хранит небольшую версионированную модель настроек. `sshconn` проверяет
файловый ключ и идентичность сервера через x/crypto/ssh. `engine` строит
типизированный JSON и запускает sing-box. `session` отвечает за единственный
фоновый процесс и собственный управляющий endpoint. `launch` готовит профиль
Firefox и окружение Claude Code. `legacy` переносит старую установку.
`app` содержит команды и формы huh; `platform` — только детали Windows/Linux.
`cmd/bundle` нужен разработчику/CI для готовых архивов.

## Сеть

Вход sing-box: mixed HTTP/SOCKS на IPv4 loopback, `set_system_proxy=false`.
Правила: reject UDP → домены Claude через SSH → частные CIDR напрямую →
явные корпоративные suffix напрямую → остальное через SSH. TLS не перехватывается.
TCP forwarding должен быть разрешён в SSHD сервера; устанавливать sing-box
на VPS для этого сценария не нужно.

Внешние имена передаются в SSH forwarding и разрешаются на VPS. Системный
resolver используется для имени самого VPS и явных прямых доменов. IP VPS
устраняет необходимость bootstrap DNS. Неизвестный внутренний hostname
не распознаётся автоматически — добавьте конкретный suffix в настройки.

Поля `direct_cidrs` допускают только loopback/RFC1918 и перечисленные
частные IPv6 сети; `direct_domains` не могут включать домены Claude или их
предков. Эти ограничения проверяются до генерации конфигурации.

## Секреты и процессы

Настройки содержат пути и публичный SSH host key, без пароля и содержимого
приватного ключа. Пароль передаётся процессам по stdin. Конфигурация sing-box
с паролем существует только в памяти. Файловые SSH CA/FIDO/аппаратные ключи
пока не поддерживаются; используйте Ed25519/RSA/ECDSA.

Для неизвестного host key требуется подтверждение fingerprint. Изменённый
или отозванный ключ не принимается автоматически. Для RSA согласуются
RSA/SHA-2, а не устаревший RSA/SHA-1.
Сохранённый ключ сверяется с `known_hosts` при каждом запуске и повторном
использовании сессии; эта локальная проверка не требует пароля приватного ключа.

`cproxy --serve` получает настройки через pipe, берёт native OS lock и
запускает единственного ребёнка sing-box. Его падение вызывает повторный
запуск через две секунды. При остановке сессии ребёнок завершается.
Linux использует parent-death signal, Windows — Job Object.
Отмена неудачного конкурентного запуска завершает только созданный им процесс,
а не сессию другого запуска, выигравшую блокировку.

Управление: случайный loopback-порт, случайный токен в приватном runtime-файле,
только GET status / POST stop. Запросы браузера с Origin и неверным токеном
отвергаются. PID не используется как основание для stop. Готовность требует
собственного управляющего процесса и HTTPS-запроса через явно заданный прокси.

Переменные proxy/NO_PROXY родительской оболочки не могут изменить маршрут
запущенного через cproxy Claude Code. Самостоятельно запущенные IDE,
background agents Claude Code и инструменты, не использующие эти переменные,
не находятся под контролем cproxy.

Выделенный Firefox запускается с `--no-remote`: cproxy не пересылает OAuth в
случайный профиль. Для уже открытого профиля показана ссылка для ручной вставки.
Активность определяется через [нативные блокировки Firefox](https://github.com/mozilla-firefox/firefox/blob/main/toolkit/profile/nsProfileLock.cpp),
а не по существованию старого lock-файла. Изменённые proxy preferences
применяются после закрытия и повторного открытия выделенного окна.
